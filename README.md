## Порівняння ефективності жадібного алгоритму та алгоритму динамічного програмування

### Жадібний алгоритм (`find_coins_greedy`)

- Працює дуже швидко (майже миттєво), оскільки просто перебирає номінали від найбільшого до найменшого.
- Часова складність: **O(n)**, де `n` — кількість номіналів (в даному випадку 6).
- **Придатний для великих сум**, особливо коли набір монет дозволяє правильно знайти мінімум (наприклад, монети 50, 25, 10, 5, 2, 1).

### Алгоритм динамічного програмування (`find_min_coins`)

- Забезпечує **оптимальний результат** (мінімальна кількість монет).
- Але значно повільніший при великих сумах, оскільки:
  - Створює масив довжиною `amount + 1`,
  - Для кожної суми перебирає всі монети.
- Часова складність: **O(amount × n)**, де `n` — кількість монет.

### Висновки:

- **Жадібний алгоритм** надзвичайно швидкий, але **може не гарантувати мінімальної кількості монет**, якщо набір номіналів не "канонічний".
- **Алгоритм динамічного програмування** — завжди дає **оптимальний результат**, але повільніший, особливо для великих сум.
- **У більшості практичних задач**, якщо набір монет є стандартним (1, 2, 5, 10…), жадібний підхід є ефективним і достатнім.
- Якщо набір монет нестандартний або потрібно **гарантувати мінімум монет**, слід використовувати динамічне програмування.
